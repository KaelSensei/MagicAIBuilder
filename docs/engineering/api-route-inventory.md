# API Route Inventory

> **Source:** a read-only security audit of `dev` at `65e6230` (#1316) on 2026-11-10. No code was run. Every finding was read from the source; the exploit sketches were reasoned, not executed. Routes added after `65e6230` are not listed, so check a row against the code before relying on it.
>
> **Updated 2026-11-10** for merges #1318 to #1325, on `dev` at `72fbfc1`. A row that a merge changed names the PR; every other row still describes `65e6230`.

This page lists every handler under `src/app/api`: 65 `route.ts` files and the edge route `og/route.tsx`. For each one it records who may call it, how the request is checked, which rate limit applies and which outside service it calls. The app runs on Vercel serverless functions with a free-tier 512 MB Postgres database.

The audit left out five issues that were already recorded: the whole deck row from `/api/share/[token]`, the `/api/combos` open proxy, the arbitrary text of `/api/og`, a deleted account re-created from its JWT, and the client-sent `isBanned`. #1325 fixed the share route, #1324 the combos proxy and #1319 the re-created account.

## Legend

- **Auth:** `-` public · `S` session (`requireAuth`) · `O` session plus owner (`requireDeckOwner`, or a `userId` in the `WHERE`) · `M` moderator · `K` API key plus scope.
- **Val:** `z` bounded zod schema · `z~` zod without size bounds · `m` manual checks · `-` none.
- **RL:** rate limit. Every limit is held in memory, per instance (M2).
- **Out:** outbound fetch.

## Cross-cutting posture

None of these is a finding unless the line says so.

- **CSRF:** every state-changing handler uses POST, PATCH, PUT or DELETE with a JSON body. The Auth.js session cookie is `SameSite=Lax`, so a cross-site write arrives without a session. No GET handler has a meaningful side effect. The `/api/v1` routes accept bearer tokens only, never a cookie.
- **IDOR:** every `[id]` route checks ownership or visibility, by a 403 or 404 after the read or by `userId` in the `WHERE`. None found.
- **Error bodies:** handlers log `error.message` and return fixed text. Zod issue messages reach clients, which is acceptable.
- **Caching:** no private JSON response sets `public` or `s-maxage`, and Vercel's CDN does not cache without `s-maxage`. As hardening, send `Cache-Control: private, no-store` from `/api/user/*`, `/api/decks*` and `/api/deck/[id]`, which returns the owner's whole deck when a cookie is present.
- **SSRF:** `proxy-card-image` fetches one host over HTTPS, and every import source rebuilds its URL from a fixed host. None found.
- **CSP:** `script-src 'unsafe-inline'` (`src/lib/security-headers.ts`) is what turns H1 from an open redirect into XSS. The nonce migration noted in that file would remove the whole class.
- **Auth guard:** every private handler calls `requireAuth`, `requireDeckOwner`, `requireModerator` or `requireApiScope` today. Nothing checks that a new route does (L2).
