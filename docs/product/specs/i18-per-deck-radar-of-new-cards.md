# Spec: Per-Deck Radar Of New Cards (I-18)

> **Initiative:** [I-18 in the roadmap](../roadmap.md) · **Status:** Later · **Researched:** 2026-11-08
> **Owns:** on-demand, per-deck shortlists from a dated set. **Does not own:** notifications, which stay in I-08 until this flow is validated.

## Overview

A new set drops roughly every six weeks. A player with eight decks wants one answer per deck: _which of these 500 cards matter here, and why?_ The radar answers on request, from a named source, and never changes the deck.

## What the market does

The spoiler-season market is large and **entirely set-centric**. Nothing found on 2026-11-08 is deck-centric.

| Source                                                                          | What it offers                                     |
| ------------------------------------------------------------------------------- | -------------------------------------------------- |
| **AetherHub**, **Draftsim**, **mtgdatabase**, **Playgroup.gg**, **Untapped.gg** | Visual spoiler galleries of every new card, by set |
| **EDHREC set pages**                                                            | Set cards ranked by early Commander inclusion      |
| **DeckCheck Deckhand reports**                                                  | Deck-aware chat reports, not tied to a set release |
| Nerdleagues, Metagame                                                           | Card lists and release schedules                   |

**The gap is the join.** Everyone publishes "here is the new set". Nobody publishes "here is what the new set means for _your_ Ur-Dragon list". That join is cheap for the product: the deck is already modelled, legality is already computed, and Scryfall already exposes a set corpus.

**Immediate context:** the Star Trek set releases **2026-11-13** with 586 cards and four Universes Beyond Commander precons — a dated corpus landing within days of this spec.

## Current state in this codebase

- `src/lib/scryfall/client.ts` — can query a set; results cached 1 h, cards 24 h.
- `src/lib/deck/bracket.ts` and colour-identity/legality validation — the filter for "legal in this deck" already exists.
- `src/lib/recommendations/` and the EDHREC integration (I-09) — source-and-freshness labelling already exists and must be reused.
- **Missing:** any set-release awareness, and any per-deck compute budget.

## Functional requirements

### 1. On request only

1.1 The radar runs when the player asks, for one deck at a time. Nothing is computed on a schedule.
1.2 The request names the set and shows the corpus date, so the player knows what was examined.
1.3 One request has a hard compute ceiling. Reaching it returns a partial, labelled result rather than running longer.

### 2. Legality first, relevance second

2.1 The set corpus is filtered to cards legal in that deck: format, colour identity, singleton and banlist.
2.2 Only cards surviving the filter are considered for relevance. No illegal card is ever shown as a candidate.

### 3. A named reason per card

3.1 Each candidate carries a reason attributed to a named source — EDHREC early inclusion, a Commander Spellbook combo with a card already in the deck, or a role the deck is measurably short of per I-03.
3.2 A reason generated by the model is labelled as AI-suggested, separately from any Scryfall or EDHREC verification, exactly as I-09 already requires.
3.3 A candidate with no attributable reason is not shown. Filling the list is not a goal.

### 4. The deck never changes by itself

4.1 Adopting a card opens the existing diff preview; the player confirms.
4.2 No bulk-apply. One card, one decision.
4.3 Dismissing a candidate is remembered for that deck and set, so a second request does not repeat it.

### 5. Deduplication

5.1 A card reachable through two reasons appears once, with both reasons listed.
5.2 Reprints already in the deck under another printing are not candidates.

## Data and API

- `POST /api/decks/{id}/radar` → `{ setCode }`, returns `{ corpusDate, truncated, candidates: [{ scryfallId, reasons: [{ source, detail, observedAt }] }] }`.
- Dismissals stored per `(deckId, setCode, scryfallId)`.
- The route reuses the Scryfall cache; a set corpus is fetched once and shared across decks and players.

## Non-goals

- Notifications, digests or e-mail. Explicitly deferred until the on-demand flow is validated; I-08 owns notifications.
- Spoiler-season coverage of unreleased cards. The corpus is a released, dated set.
- Automatic deck modification, under any setting.
- Ranking decks against each other.

## Testing strategy

- **Solitary:** the legality filter over a fixture set returns only cards legal in the fixture deck, including the colour-identity and singleton edges.
- **Contract:** every returned candidate carries at least one reason with a source and an `observedAt`; a reasonless candidate fails the test.
- **Boundary:** a dismissed card does not reappear; the same card reachable by two reasons appears once with two reasons.
- **Budget:** a corpus exceeding the ceiling returns `truncated: true` and a partial list, never a timeout.

## Open questions

- Which signal carries the most weight early in a set's life, when EDHREC has almost no data? A combo with a card already in the deck is deterministic and available on day one; inclusion data is not. Starting with combos may be both cheaper and more honest.
- Four Universes Beyond precons shipping with a set (Star Trek, 2026-11-13) blur "new cards" and "precon contents". Does the radar consider precon-only cards, which many players will never own as singles?
